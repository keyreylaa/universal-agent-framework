# Claude Code — extension surface capability notes (as of 2026-10-16)

Basis: official docs at code.claude.com (Anthropic's Claude Code docs) + github.com/anthropics/claude-code.
Citations: `docs:/PATH` = https://code.claude.com/docs/en/PATH (full URLs in Sources). All facts below were read from those pages on 2026-10-16.

## Verified facts

### 1. Skills
- **Format**: one directory per skill holding `SKILL.md` — YAML frontmatter between `---` markers that must start on line 1, then Markdown instructions. Unparsable YAML still loads the skill with no fields; unknown keys are ignored silently. `docs:/skills#frontmatter-reference`
- **Locations**: enterprise/managed `.claude/skills/<name>/SKILL.md`; personal `~/.claude/skills/<name>/SKILL.md`; project `.claude/skills/<name>/SKILL.md`; nested `<subdir>/.claude/skills/…`; a `--add-dir` directory's `.claude/skills/`; plugin `<plugin>/skills/<name>/SKILL.md` (invoked as `/plugin:skill`); claude.ai account skills synced to `~/.claude/skills/synced/` under reserved namespace `anthropic-skills:`. `docs:/skills#where-skills-live`
- **Discovery**: project skills load from the launch dir and every parent up to the repo root; a nested `.claude/skills/` *below* the launch dir is not loaded at startup — it loads the first time Claude reads/edits a file there and is absent from the `/` menu until then. Symlinked skill folders are followed and de-duplicated. `docs:/skills#discovery-from-parent-and-nested-directories`
- **Progressive disclosure**: (a) a per-turn listing of every skill's `name` + `description` (+`when_to_use`); (b) on invoke, the rendered `SKILL.md` enters the conversation as one message and stays across turns (not re-read on later turns); (c) extra files (`reference.md`, `scripts/`) are read on demand by Claude's own file tools. `docs:/skills#skill-content-lifecycle`, `docs:/skills#add-supporting-files`
- **Activation**: model-invoked automatically when the description matches, and/or user-invoked by starting a message with `/skill-name`. `disable-model-invocation: true` = Claude can't invoke; `user-invocable: false` = hidden from the `/` menu and not runnable by the user. `docs:/skills#control-who-invokes-a-skill`
- **Frontmatter keys** (all optional; `description` recommended): `name`, `description`, `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context` (`fork` = run in a subagent), `agent`, `background`, `hooks`, `paths`, `shell`, `metadata`, `license`, `compatibility`. `docs:/skills#frontmatter-reference`
- **`allowed-tools`**: space/comma string or YAML list of tool names or rules such as `Bash(git add *)`; pre-approves only for the turn that invoked the skill and is cleared by the user's next message; it never restricts the available tool pool (use `disallowed-tools`), and is ignored for project/personal skills when managed `allowManagedPermissionRulesOnly` is set. `docs:/skills#pre-approve-tools-for-a-skill`
- **Sizes/limits**: `description` + `when_to_use` are truncated at **1,536 characters** in the listing; guidance is to keep `SKILL.md` **under 500 lines**; the listing budget defaults to **1% of the model context window** and over-budget listings drop descriptions of least-used skills (settings `skillListingBudgetFraction`, `skillListingMaxDescChars`); `compatibility` ≤ 500 chars; names may not contain `<`, `>`, zero-width/control/bidi/private-use chars or unusual whitespace; folder names `synced` and `anthropic-skills` are reserved. `docs:/skills#frontmatter-reference`, `docs:/skills#skill-descriptions-are-cut-short`, `docs:/settings-reference#skilllistingbudgetfraction`
- **Substitutions**: `$ARGUMENTS`, `$ARGUMENTS[N]`, `$N`, named `$name` (declared in `arguments:`), plus `${CLAUDE_SESSION_ID}`, `${CLAUDE_EFFORT}`, `${CLAUDE_SKILL_DIR}`, `${CLAUDE_PROJECT_DIR}`, `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`; args passed with no placeholder are appended as `ARGUMENTS: <value>`; `\$1` escapes a literal. `docs:/skills#available-string-substitutions`
- **Dynamic context**: `` !`cmd` `` or a ```` ```! ```` fenced block runs a shell command before the body reaches Claude and inlines stdout; a failing command aborts the whole skill invocation. `docs:/skills#inject-dynamic-context`
- **Command name resolution**: directory name, overridden by frontmatter `name`; a skill beats a same-named `.claude/commands/*.md` file; enterprise > personal > project; plugin skills always keep the `/plugin:` prefix. `docs:/skills#how-a-skill-gets-its-command-name`

### 2. Plugins
- **Manifest**: `.claude-plugin/plugin.json` at the plugin root; optional (components in their default folders load anyway). Only `name` is required (kebab-case, no spaces/`@`/`:`/separators). Other keys: `displayName`, `version`, `description`, `author`, `homepage`, `repository`, `license`, `keywords`, `metadata`, `icon`, `documentationUrl`, `supportUrl`, `privacyPolicyUrl`, `termsOfServiceUrl`, `defaultEnabled`, `dependencies`, `settings`, `userConfig`, `channels`, `types`, and the component keys `skills`, `commands`, `agents`, `hooks`, `mcpServers`, `lspServers`, `outputStyles`, `workflows`, `experimental.{themes,monitors,evals}`. `docs:/plugins/manifest-reference#fields`
- **Marketplace file**: `.claude-plugin/marketplace.json` in the marketplace root; requires `name`, `owner`, `plugins[]`; each entry requires `name` + `source` (relative path from the marketplace root, or an object with `source: github|url|git-subdir|npm|archive|command`). `strict` (default true) controls whether an entry may add components to a plugin that has its own `plugin.json`. `docs:/plugins/marketplace-reference#marketplace-file`, `docs:/plugins/create-marketplace`
- **What a plugin bundles** (default layout under the plugin root): `skills/<name>/SKILL.md`, `commands/*.md`, `agents/*.md`, `hooks/hooks.json`, `.mcp.json`, `.lsp.json`, `output-styles/`, `workflows/`, `themes/`, `monitors/monitors.json`, `bin/` (added to Bash `PATH`), `settings.json` (only `agent` and `subagentStatusLine` apply), plus `.claude-plugin/plugin.json`. Every path in the manifest is relative to the plugin root, must start with `./`, and must resolve inside the root. `docs:/plugins/manifest-reference#standard-layout`, `docs:/plugins/manifest-reference#path-rules`
- **Install/management**: in-session `/plugin` (Discover/Installed/Marketplaces tabs), `/plugin install <name>@<marketplace>`, `/plugin marketplace add <owner/repo|git-url|local-path>`, `/plugin enable|disable|uninstall`, `/reload-plugins`; shell equivalents `claude plugin install|uninstall|enable|disable|update|list|details|prune|configure|validate|eval` and `claude plugin marketplace add|list|remove`; one-shot `--plugin-dir <dir|zip>`, `--plugin-url <zip url>`, and `--marketplace <source>` on an install. `docs:/plugins/install`, `docs:/plugins/cli-reference`
- **Scopes**: user (`~/.claude/settings.json`), project (`.claude/settings.json`, shared via git), local (`settings.local.json`); recorded in `enabledPlugins`. Plugin skills/commands are namespaced `/plugin-name:component`; plugin agents as `plugin:sub:agent`. `docs:/plugins/install#choose-an-install-scope`

### 3. Slash commands
- **Format**: Markdown files in `.claude/commands/*.md` (project) or `~/.claude/commands/*.md` (user); the file name without extension is the command. Custom commands are now the same mechanism as skills, and skill files are the recommended form: "A file at `.claude/commands/deploy.md` and a skill at `.claude/skills/deploy/SKILL.md` both create `/deploy` and work the same way." `docs:/skills#where-skills-live`
- **Frontmatter**: a command file accepts **the same fields as skill frontmatter except `name` and `paths`** — i.e. `description`, `argument-hint` (autocomplete hint such as `[issue-number]`), `allowed-tools`, `disallowed-tools`, `model`, `effort`, `arguments`, `disable-model-invocation`, `user-invocable`, `context`/`agent`, `hooks`, `shell`, `metadata`, `license`, `compatibility`. `docs:/claude-directory#frontmatter-fields-by-file`, `docs:/skills#frontmatter-reference`
- **Arguments**: `$ARGUMENTS` (whole trailing string), `$ARGUMENTS[N]` (0-based), `$N` shorthand, `$name` from the `arguments:` list; shell-style quoting groups multi-word args; leftover args are appended as `ARGUMENTS: <value>`. Up to 6 stacked `/skill` invocations expand in one message. `docs:/skills#pass-arguments-to-skills`
- **Namespacing by subdirectory**: `.claude/commands/frontend/component.md` → `/frontend:component` (each `/` becomes `:`); a plugin command file/dir `commands/foo.md` in plugin `deploy-tools` → `/deploy-tools:foo`, and an object-map key `about` → `/deploy-tools:about`. `docs:/skills#how-a-skill-gets-its-command-name`, `docs:/plugins/manifest-reference#commands`
- Built-in/bundled commands (e.g. `/help`, `/compact`, `/debug`, `/code-review`, `/doctor`, `/verify`) are documented separately; a same-named user skill replaces the built-in command but not its aliases. `docs:/commands`, `docs:/skills#resolve-skills-that-share-a-name`

### 4. Subagents
- **Files**: Markdown + YAML frontmatter in `.claude/agents/*.md` (project, scanned recursively up to the repo root), `~/.claude/agents/*.md` (user), managed settings' `.claude/agents/`, a plugin's `agents/` (scoped `plugin:sub:name`), or inline JSON via `--agents`. Precedence: managed > `--agents` > project > user > plugin. `docs:/sub-agents#choose-the-subagent-scope`
- **Required frontmatter**: `name` (≤ 256 chars, no `:`, hooks receive it as `agent_type`; the filename need not match) and `description` (drives delegation). Missing `name` or `description` ⇒ the file is skipped with a debug-log entry. `docs:/sub-agents#supported-frontmatter-fields`
- **Optional frontmatter**: `tools` (comma string or YAML list; inherits all subagent tools if omitted), `disallowedTools`, `model` (`sonnet|opus|haiku|fable`, full model ID, or `inherit`), `permissionMode` (`default|acceptEdits|auto|dontAsk|bypassPermissions|plan`, `manual` alias), `maxTurns`, `autoCompactWindow`, `skills` (preloads full skill bodies), `mcpServers`, `hooks`, `memory` (`user|project|local`), `background`, `omitClaudeMd`, `effort`, `isolation` (`worktree`), `color`, `initialPrompt`, `experimental.cacheTtl`. Plugin subagents ignore `hooks`, `mcpServers`, `permissionMode`. `docs:/sub-agents#supported-frontmatter-fields`
- The body is the subagent's system prompt; it gets that plus env details, not Claude Code's system prompt. Subagents can nest up to 3 layers below the main conversation. `docs:/sub-agents#write-subagent-files`

### 5. Hooks
- **Config location**: the `hooks` key of any settings file — `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, managed policy settings — plus a plugin's `hooks/hooks.json`, and skill/subagent frontmatter (`hooks:`). Hook entries *merge* across levels rather than replacing. `docs:/hooks#hook-locations`
- **Schema** (three nesting levels: event → matcher group → handlers):
  `{"hooks": {"PreToolUse": [{"matcher": "Bash|PowerShell", "hooks": [{"type": "command", "if": "Bash(rm *)", "command": "./.claude/hooks/block-rm.sh", "timeout": 600}]}]}}` `docs:/hooks#configuration`
- **Handler types**: `"command"`, `"http"`, `"mcp_tool"`, `"prompt"` (LLM judge), `"agent"` (experimental subagent verifier). Common handler fields: `type`, `if` (one permission rule, tool events only), `timeout` (600s command/http/mcp_tool, 30s prompt, 60s agent), `statusMessage`, `once` (skill frontmatter only). Command hooks add `command`, `args` (exec form), `async`, `asyncRewake`, `shell` (`bash|powershell`). `docs:/hooks#hook-handler-fields`
- **Matcher semantics**: `"*"`, `""`, or omitted = every occurrence; a value of only letters/digits/`_`/`-`/space/`,`/`|` is an exact name or a list separated by `|` or `,`; anything else is an unanchored JavaScript regex (`Edit.*` also matches `NotebookEdit`; use `^Edit$`). `FileChanged` and `StopFailure` accept only letters/digits/`_`/`|`. `docs:/hooks#matcher-patterns`
- **Events** (33): `SessionStart`, `Setup`, `InstructionsLoaded`, `UserPromptSubmit`, `UserPromptExpansion`, `MessageDisplay`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`, `PermissionDenied`, `Notification`, `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `Stop`, `StopFailure`, `TeammateIdle`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`, `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`, `SessionEnd`, `Elicitation`, `ElicitationResult`. `docs:/hooks#hook-events`
- **stdin JSON (command hooks; POST body for HTTP)**: common fields `session_id`, `prompt_id`, `transcript_path`, `cwd`, `scratchpad_dir`, `permission_mode`, `effort.level`, `hook_event_name`, plus `agent_id`/`agent_type` inside subagents; event-specific fields are added, e.g. `PreToolUse` receives `tool_name`, `tool_input`, `tool_use_id`, `SessionStart` receives `source`, `Stop` receives `last_assistant_message`. `docs:/hooks#common-input-fields`
- **Exit codes**: `0` = success (JSON fields on stdout are applied); `2` = blocking error on events that can block (e.g. `PreToolUse` blocks the tool call, `UserPromptSubmit` rejects the prompt), stdout JSON still parsed but cannot override the block; any other code (or a crash/unparsable JSON) = non-blocking error, action proceeds unless `"onFailure": "block"` is set. `WorktreeCreate`/`WorktreeRemove` treat any non-zero exit as failure. `docs:/hooks#exit-code-output`, `docs:/hooks#exit-code-2-behavior-per-event`
- **JSON output**: `continue`, `stopReason`, `systemMessage`, `terminalSequence`, top-level `decision`/`reason`, and event-specific `hookSpecificOutput` (requires `hookEventName`) — e.g. `PreToolUse` returns `permissionDecision: allow|deny|ask|defer` + `permissionDecisionReason`; `SystemMessage`/`additionalContext`/plain stdout capped at 10,000 chars. `docs:/hooks#json-output`
- **Disable/policy**: `disableAllHooks`, managed `allowManagedHooksOnly`, `allowedHttpHookUrls`, `httpHookAllowedEnvVars`; `/hooks` shows the loaded set; debug log via `--debug`/`--debug-file`. `docs:/hooks#disable-or-remove-hooks`

### 6. Settings
- **Files**: user `~/.claude/settings.json`; project `.claude/settings.json` (committed); project-local `.claude/settings.local.json` (gitignored, personal overrides); managed policy settings deployed by the org. Files are strict JSON — a comment or trailing comma is a "Settings Error". `docs:/settings#settings-files-and-who-they-affect`
- **Precedence, highest first**: (1) managed settings, (2) `--settings <file-or-json>` (session only), (3) `.claude/settings.local.json`, (4) `.claude/settings.json`, (5) `~/.claude/settings.json`. List keys such as `permissions.allow` **merge** across files instead of overriding. `docs:/settings#settings-precedence`
- **Permission keys**: `permissions.allow`, `permissions.ask`, `permissions.deny` (deny also hides matching files from Read/search and blocks Edit/Write), `permissions.additionalDirectories`, `permissions.defaultMode`, `permissions.disableBypassPermissionsMode`, `permissions.blockReadsOutsideWorkingDirectories`; `allowManagedPermissionRulesOnly` makes managed settings the only source of rules (ignoring `allowed-tools`, `--allowedTools`). `docs:/settings-reference#permission-settings`
- **`permissions.defaultMode` values**: `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`, and `manual` as an alias for `default`; `auto` and `bypassPermissions` are not honored from project/local files (set them in user settings). `docs:/settings-reference#permissionsdefaultmode`
- Settings edits hot-reload into the running session; `/status` lists the sources actually loaded. `docs:/settings#when-edits-take-effect`

### 7. Memory / context files
- **`CLAUDE.md` load order** (broadest → most specific): managed policy file (`/Library/Application Support/ClaudeCode/CLAUDE.md` on macOS, `/etc/claude-code/CLAUDE.md` on Linux/WSL, `C:\Program Files\ClaudeCode\CLAUDE.md` on Windows) → user `~/.claude/CLAUDE.md` → project `./CLAUDE.md` or `./.claude/CLAUDE.md` → local `./CLAUDE.local.md`. All discovered files are concatenated (root → working directory; `CLAUDE.local.md` after `CLAUDE.md` per directory), and files in subdirectories load on demand. `docs:/memory#choose-where-to-put-claude-md-files`, `docs:/memory#how-claude-md-files-load`
- **`@import`**: `@path/to/file` inside a CLAUDE.md; relative paths resolve against the importing file; recursion allowed to 4 hops; backslash-escape spaces (`@Design\ Docs/api.md`); quoted paths and code spans are not imported; imports resolving outside the working directory prompt a one-time approval dialog. `docs:/memory#import-additional-files`
- **Rules**: `.claude/rules/*.md` (project) and `~/.claude/rules/`, discovered recursively; rules without frontmatter load at launch with `.claude/CLAUDE.md` priority; a rule with `paths:` frontmatter (glob list, e.g. `src/api/**/*.ts`) loads only when Claude touches matching files; brace expansion shares a budget of 1,000 expanded patterns / 4 MiB. `docs:/memory#organize-rules-with-claude-rules`
- **`AGENTS.md`**: read instead of `CLAUDE.md` when no `CLAUDE.md` exists in the working directory or above; switchable via `/config` → **Project instructions**. `docs:/memory#agents-md`
- **Auto memory**: on by default in local sessions; Claude writes `user|feedback|project|reference` notes into `~/.claude/projects/<project>/memory/` (`MEMORY.md` index + one topic file per memory). Only the first 200 lines / 25 KB of `MEMORY.md` load at session start; topic files load on demand. Controls: `autoMemoryEnabled`, `autoMemoryDirectory`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. `docs:/memory#auto-memory`
- A `CLAUDE.md` is loaded up to 4 MiB (larger is skipped); docs advise under 200 lines; block-level HTML comments are stripped. `docs:/memory#auto-memory`, `docs:/memory#write-effective-instructions`

### 8. MCP
- **Add commands**: `claude mcp add --transport http <name> <url> [--header "Authorization: Bearer …"]`; SSE via `--transport sse` (deprecated); stdio via `claude mcp add [--env K=V] --transport stdio <name> -- <command> [args…]` (everything after `--` goes to the server); WebSocket servers only through `.mcp.json` / `claude mcp add-json`. `docs:/mcp#installing-mcp-servers`
- **Transports**: `http` (alias `streamable-http`; an entry with `url` but no `type` is an error), `sse`, `ws`, `stdio`; `"type": "sdk"` entries are only valid in an SDK host and are skipped elsewhere. `docs:/mcp#option-1-add-a-remote-http-server`
- **Scopes**: **local** (default; stored per-project under `~/.claude.json`, private), **project** (`.mcp.json` at the repo root, committed, approval prompt in interactive sessions), **user** (`~/.claude.json`, all your projects). Managed/server-provided config is also supported. Precedence and stability: `.mcp.json` shape is `{"mcpServers": {"<name>": {"type": "http", "url": "…"}}}`. `docs:/mcp#mcp-installation-scopes`
- **Management**: `claude mcp list|get <name>|remove <name>|add-json|reset-project-choices`, `/mcp` panel for status/auth/toggle, `disabledMcpjsonServers` / `enabledMcpjsonServers` / `enableAllProjectMcpServers`, `--mcp-config`, `--strict-mcp-config`. `docs:/mcp#managing-your-servers`
- Plugin-provided servers: a plugin's `.mcp.json` or the manifest's `mcpServers` (`.json` file, `.mcpb`/`.dxt` bundle, URL, or inline map). `docs:/mcp#plugin-provided-mcp-servers`

### 9. CLI / non-interactive mode and config dir
- **Non-interactive flags**: `--print`/`-p`; `--output-format text|json|stream-json`; `--input-format text|stream-json`; `--permission-mode default|acceptEdits|plan|auto|dontAsk|bypassPermissions|manual` (overrides `defaultMode`); `--allowedTools`/`--allowed-tools` (pre-approve, overrides same-named settings) and `--disallowedTools`; `--settings <file-or-json>` (≤ 2 MiB); `--setting-sources user,project,local`; `--add-dir`; `--mcp-config` / `--strict-mcp-config`; `--agents <json|file>`; `--plugin-dir` / `--plugin-url`; `--max-turns`; `--max-budget-usd`; `--json-schema`; `--verbose`; `--include-partial-messages`; `--dangerously-skip-permissions`; `--bare` and `--safe-mode` (skip auto-discovery of skills/plugins/hooks/MCP/CLAUDE.md). `docs:/cli-reference#cli-flags`
- **Config/state dir**: `~/.claude/` (Windows `%USERPROFILE%\.claude`), overridden entirely by `CLAUDE_CONFIG_DIR`. It holds `settings.json`, `CLAUDE.md`, `rules/`, `skills/`, `commands/`, `agents/`, `workflows/`, `output-styles/`, `projects/<project>/memory/`, `debug/<session-id>.txt`, `keybindings.json`, `themes/`. App state, OAuth credentials, UI toggles and personal MCP servers live in `~/.claude.json`. Project scope is the repo's `.claude/` plus root `CLAUDE.md`, `.mcp.json`, `.worktreeinclude`. `docs:/claude-directory`
- `/status` shows the settings sources in effect; `claude doctor` runs read-only install diagnostics. `docs:/settings#confirm-what-loaded`
