# OpenAI Codex CLI — extension surface capability notes (as of 2026-10-16)

Basis: official Codex docs (`developers.openai.com/codex/*`, served from `learn.chatgpt.com/docs/*`) and the official `openai/codex` repo (`codex-rs/`). Doc URLs listed in Sources; repo paths are `path:line` where a line is cited. Anything not found is marked UNVERIFIED.

## Verified facts

### 1. Instruction files (`AGENTS.md`)
- Discovery (once per run; TUI = once per launched session): **global scope** = `$CODEX_HOME/AGENTS.override.md` if present, else `$CODEX_HOME/AGENTS.md`; only the first non-empty file at this level is used. **Project scope** = walk from project root (normally the Git root) down to CWD; in every directory check `AGENTS.override.md` → `AGENTS.md` → each name in `project_doc_fallback_filenames`; at most one file per directory.
- Merge order: concatenated root→CWD joined by blank lines; files closer to CWD appear later and therefore override earlier guidance. Empty files are skipped. Collection stops when the combined size reaches `project_doc_max_bytes` (prose: 32 KiB default).
- Root detection: `.git` by default; `project_root_markers = [".git", ".hg", ".sl"]` to change; `project_root_markers = []` ⇒ CWD is the root (no parent search). If no root is found only CWD is checked.
- Keys: `project_doc_max_bytes` (number), `project_doc_fallback_filenames` (array<string>), `model_instructions_file` (path; replaces built-in instructions instead of `AGENTS.md`), `developer_instructions` (string, extra developer instructions injected), `instructions` (string, "reserved for future use"). Source: config reference; docs/agents_md.md redirects to the guide.
- Operational: `codex --cd services/payments …`, `CODEX_HOME=$(pwd)/.codex codex exec …`; `/init` scaffolds an `AGENTS.md`; `/status` reports workspace root; audit via `codex -c log_dir=./.codex-log` → `.codex-log/codex-tui.log`, or `/debug-config`.

### 2. `config.toml` and `$CODEX_HOME`
- `CODEX_HOME` (default `~/.codex`; if set the directory must already exist) is the root for "config, auth, logs, sessions, skills, and standalone package metadata". `CODEX_SQLITE_HOME` (default `CODEX_HOME`) moves SQLite state; config key `sqlite_home` wins over the env var.
- Files/layers: `$CODEX_HOME/config.toml`; per-profile `$CODEX_HOME/<name>.config.toml` selected with `--profile <name>`/`-p` (top-level keys, **not** `[profiles.<name>]`; since 0.134.0 `--profile` no longer reads `[profiles.*]` and the top-level `profile` selector is gone); project `.codex/config.toml` from project root → CWD (closest wins, loaded **only for trusted projects**); managed `requirements.toml` on top. `-c/--config key=value` (parsed as TOML, dot notation e.g. `mcp_servers.x.enabled=false`) overrides for one invocation.
- Project-local `.codex/config.toml` **ignores** (with startup warning): `openai_base_url`, `chatgpt_base_url`, `apps_mcp_product_sku`, `model_provider`, `model_providers`, `notify`, `profile`, `profiles`, `experimental_realtime_ws_base_url`, `otel`.
- Model/provider: `model`, `review_model`, `model_provider` (default `openai`), `openai_base_url`, `model_context_window`, `model_auto_compact_token_limit`, `model_auto_compact_token_limit_scope` (`total|body_after_prefix`), `model_catalog_json`, `oss_provider` (`lmstudio|ollama`), `model_reasoning_effort` (`low|medium|high|xhigh|max|ultra`), `model_reasoning_summary` (`auto|concise|detailed|none`), `model_verbosity` (`low|medium|high`), `model_supports_reasoning_summaries`, `service_tier`, `[model_providers.<id>]` = `name`, `base_url`, `wire_api` (only `responses`), `env_key`, `env_key_instructions`, `experimental_bearer_token`, `requires_openai_auth`, `query_params`, `http_headers`, `env_http_headers`, `request_max_retries` (4), `stream_max_retries` (5), `stream_idle_timeout_ms` (300000), `supports_websockets`, `supports_standalone_web_search`, `model_catalog_url`, `capabilities.external_web_access|remote_compaction`, `auth.command/args/timeout_ms/refresh_interval_ms/cwd`; built-in `amazon-bedrock` with `[model_providers.amazon-bedrock.aws] profile/region`. Reserved provider ids that cannot be overridden: `openai`, `ollama`, `lmstudio`.
- Approvals/sandbox: `approval_policy = "on-request" | "never" | { granular = { sandbox_approval, rules, mcp_elicitations, request_permissions, skill_approval } }` (`untrusted` is **unsupported/retired**, `on-failure` deprecated); `approvals_reviewer = "user" | "auto_review"`; `auto_review.policy`, `auto_review.extra_policy`; `sandbox_mode = "read-only" | "workspace-write" | "danger-full-access"`; `[sandbox_workspace_write]` = `writable_roots` (array), `network_access` (bool), `exclude_tmpdir_env_var`, `exclude_slash_tmp`; `[windows] sandbox = "mxc|elevated|unelevated"`; `features.prefer_mxc`; `[projects."/abs/path"] trust_level = "untrusted"` (project-level trust entry, still supported); `allow_login_shell`.
- Tools/web: `tools.web_search = true|false|{ context_size="low|medium|high", allowed_domains=[…], location={country,region,city,timezone} }`, `tools.view_image` (bool), top-level `web_search = "disabled|cached|indexed|live"` (default `cached`; `--search` ⇔ `live`), `tool_output_token_limit`, `tool_suggest.discoverables[]` (`type="connector"|"plugin"`, `id`), `tool_suggest.disabled_tools[]`.
- MCP: `[mcp_servers.<id>]` — see §6. Subagents: `[agents]` — see §5.
- History/state: `[history] persistence = "save-all" | "none"`, `history.max_bytes`; `compact_prompt`, `experimental_compact_prompt_file`; `log_dir` (default `$CODEX_HOME/log`; setting it enables the plaintext `codex-tui.log`), `sqlite_home`.
- Notify/TUI: `notify = ["cmd", "arg", …]` (array<string>, "Command invoked for notifications; receives a JSON payload from Codex"); `[tui]` = `notifications` (bool | array of event types), `notification_method = "auto|osc9|bel"`, `notification_condition = "unfocused|always"`, `animations`, `disable_paste_burst`, `alternate_screen = "auto|always|never"`, `resume_cwd = "current|session"`, `vim_mode_default`, `raw_output_mode`, `show_tooltips`, `auto_recap`, `show_server_version_notice`, `status_line` (array|null), `terminal_title` (array|null, default `["spinner","project"]`), `theme`, `keymap.<context>.<action>` (contexts incl. `global`, `chat`, `composer`, `editor`, `vim_normal`, `vim_operator`, `vim_text_object`, `pager`, `list`, `approval`; `[]` unbinds).
- Misc: `file_opener` (`vscode|vscode-insiders|windsurf|cursor|none`), `hide_agent_reasoning`, `show_raw_agent_reasoning`, `disable_paste_burst` (legacy), `check_for_update_on_startup`, `feedback.enabled`, `analytics.enabled`, `personality` (deprecated), `skills.max_context_tokens`, `skills.config`, `[features]` flags (`apps`, `hooks`, `memories`, `multi_agent`, `unified_exec`, `shell_snapshot`, `remote_plugin`, `fast_mode`, `ultrafast_mode`, `network_proxy`, `skill_mcp_dependency_install`, `prevent_idle_sleep`, `plugin_sharing`, `browser_use*`, `computer_use`, …).
- CLI overrides (source of truth `codex-rs/utils/cli/src/shared_options.rs`): `--image/-i`, `--model/-m`, `--oss`, `--local-provider`, `--profile/-p`, `--sandbox/-s`, `--approve-for-me` (alias `--not-so-yolo`), `--dangerously-bypass-approvals-and-sandbox` (alias `--yolo`), `--dangerously-bypass-hook-trust`, `--cd/-C`, `--worktree`, `--add-dir`; plus base-command `--ask-for-approval/-a {on-request|never}`, `--search`, `--no-alt-screen`, `--no-daemon`, `--strict-config` (`codex-rs/tui/src/cli.rs:74-89`) and `--enable/--disable <feature>`.

### 3. Custom prompts / slash commands
- Location: `$CODEX_HOME/prompts/*.md` (e.g. `~/.codex/prompts/draftpr.md`). **Top-level Markdown files only** — subdirectories are not scanned, non-Markdown files are ignored. Prompts are local to the Codex home and "not shared through your repository"; **no project-level prompt directory is documented**. Feature is **deprecated** ("Use skills for reusable instructions").
- Frontmatter: `description:` (shown in the popup), `argument-hint: [FILES=<paths>] [PR_TITLE="<title>"]`.
- Substitution: `$1`…`$9` positional; `$ARGUMENTS` (all); named placeholders as uppercase names (`$FILE`, `$TICKET_ID`) supplied as `KEY=value` (quote values with spaces); `$$` emits a literal `$`.
- Surfaces as `/prompts:<file-name>` (e.g. `/prompts:draftpr`) in CLI and IDE extension; management = edit/delete files, restart Codex (or open a new chat) to reload; metadata+placeholders are resolved at session start.
- Built-in slash commands (CLI): `/permissions`, `/ide`, `/keymap`, `/vim`, `/setup-default-sandbox`, `/agents`, `/subagents`, `/apps`, `/plugins`, `/hooks`, `/clear`, `/rename`, `/archive`, `/delete`, `/compact`, `/copy`, `/diff`, `/exit`|`/quit`, `/experimental`, `/approve`, `/memories`, `/skills`, `/import` (imports Claude Code/Cursor setups), `/feedback`, `/init`, `/logout`, `/mcp`, `/mention`, `/model`, `/fast`, `/plan`, `/goal`, `/ps`, `/stop`, `/fork`, `/app`, `/side`|`/btw`, `/raw`, `/resume`, `/new`, `/review`, `/status`, `/usage`, `/debug-config`, `/statusline`, `/title`, `/theme`, `/pets`, `/tui`, `/export`, `/recap`, `/cd`, `/pwd`|`/cwd`, `/worktree`, `/daemon`, `/warnings`. Type `/cmd` then `Tab` to queue a command for the next turn.

### 4. Skills — SUPPORTED (not `.codex/skills`)
- Format: a directory containing `SKILL.md` with YAML frontmatter requiring `name` and `description`, plus Markdown instructions; optional `scripts/`, `references/`, `assets/`, and `agents/openai.yaml` metadata. Built on the open agent-skills standard (agentskills.io).
- `agents/openai.yaml`: `interface.display_name|short_description|icon_small|icon_large|brand_color|default_prompt`, `policy.allow_implicit_invocation` (default `true`), `dependencies.tools[]` (`type="mcp"`, `value`, `description`, `transport="streamable_http"`, `url`).
- Discovery paths (docs table verbatim): REPO `$CWD/.agents/skills`, REPO parents up to repo root when inside a Git repo, REPO `$REPO_ROOT/.agents/skills`, USER `$HOME/.agents/skills`, ADMIN `/etc/codex/skills`, SYSTEM bundled with Codex (skill-creator, plan, …). Symlinked skill folders are followed. Same `name` in two places is **not** merged — both appear.
- Activation: implicit via matching `description`, or explicit `$skill`-mention in the CLI/IDE (and `/skills` picker to browse). Progressive disclosure: only name+description (and path in Codex) are listed initially; full `SKILL.md` is read when selected.
- Budget/controls: `skills.max_context_tokens` (integer; default 2% of the model context window, capped at `10000`); disable with `[[skills.config]] path = "/path/to/skill/SKILL.md"` + `enabled = false`. Built-in helpers: `$skill-creator`, `$skill-installer <name>` (e.g. `$skill-installer linear`). Changes are detected automatically; restart if not.

### 5. Plugins / marketplace / subagents (extension mechanisms)
- **Plugins** bundle skills + MCP server connections + browser extensions + hooks, in one universal directory shared with ChatGPT; available in ChatGPT desktop app and **Codex CLI** (not the IDE extension). CLI: `/plugins` browser (marketplace tabs, install/uninstall, Space toggles enabled) or `codex plugin add|list|remove` and `codex plugin marketplace add|list|upgrade|remove`; `codex plugin marketplace add` accepts `owner/repo`, `owner/repo@ref`, HTTP(S)/SSH Git URLs, or a local directory, with `--ref` and repeatable `--sparse PATH`. `--json` outputs documented (`pluginId`, `name`, `marketplaceName`, `version`, `installedPath`, `authPolicy`, `marketplaceSource`, …).
- Marketplace/admin knobs: `[features] remote_plugin`, `[marketplaces] restrict_to_allowed_sources` + `allowed_sources.<name>.source = git|host_pattern|local` (`url`, `ref`, `host_pattern`, `path`) in managed `requirements.toml`; `features.plugin_sharing`. Plugin hooks ship as `hooks/hooks.json` (or manifest lifecycle config) and follow the same trust review as other non-managed hooks.
- **Subagents / custom agents**: built-ins `default`, `worker`, `explorer`. Custom agents are standalone TOML files in `~/.codex/agents/` (personal) or `.codex/agents/` (project). Required keys: `name`, `description`, `developer_instructions`; optional `model`, `model_reasoning_effort`, `model_reasoning_summary`, `model_verbosity`, `[[skills.config]]`, and capability-disabling feature keys (`features.shell_tool`, `features.apps`, `features.plugins`, `features.memories`, `features.request_permissions_tool`, `skills.bundled.enabled`, `skills.include_instructions`). A custom agent **cannot** override `sandbox_mode`, `approval_policy`, `model_provider`, `mcp_servers`, or the service tier (those come from the parent). `[agents]` globals: `enabled` (default true), `max_concurrent_threads_per_session` (legacy alias `max_threads`), `default_subagent_model`, `default_subagent_reasoning_effort`, `interrupt_message`. Inspect/steer with `/subagents`. Spawning is triggered by an explicit request or by `AGENTS.md`/skill instructions; subagents inherit the session's sandbox/approval policy.

### 6. MCP
- Config lives in `~/.codex/config.toml` or project-scoped `.codex/config.toml` (trusted projects only); shared by Codex CLI, desktop app, IDE extension.
- **stdio** table: `command` (required), `args`, `env` (map), `env_vars` (array of `"NAME"` or `{ name = "NAME", source = "local"|"remote" }`), `cwd`, `experimental_environment = "remote"`.
- **streamable HTTP** table: `url` (required), `auth = "oauth" | "chatgpt"`, `bearer_token_env_var` (env var holding the bearer token for `Authorization`), `http_headers` (map), `env_http_headers` (map), `http_headers_helper` (local command printing a JSON header object; refresh-once on 401/403), `oauth.client_id`, `oauth.client_secret`, `oauth.callback_url`, `oauth.callback_port`, `scopes`, `oauth_resource`.
- Shared/common keys: `enabled`, `required` (fail startup/resume if it can't initialize), `startup_timeout_sec` (default 10) and alias `startup_timeout_ms`, `tool_timeout_sec` (default 60), `enabled_tools`, `disabled_tools` (applied after enabled), `default_tools_approval_mode = auto|prompt|writes|approve`, `tools.<tool>.approval_mode`, `tools.<tool>.output_token_limit`; top-level `mcp_optional_startup_grace_ms` (default 1000; `0` = wait each server's startup timeout).
- Transports supported: **STDIO** (local process) and **streamable HTTP** (URL); bearer-token, OAuth (CIMD/DCR) and ChatGPT session auth for the trusted first-party origin. Codex reads the MCP `instructions` field returned at initialization as server-wide guidance (keep the first 512 chars self-contained). Managed allowlisting via requirements `mcp_servers.<id>.identity.command|url` (exact/prefix/regex matchers).
- Subcommands (`codex-rs/cli/src/mcp_cmd.rs:74-81`): `list [--json]`, `get <name> [--json]`, `add`, `remove`, `login`, `logout`. `codex mcp add <name> --env K=V -- <stdio command> …`; HTTP form `codex mcp add <name> --url https://… ` with `--bearer-token-env-var`, `--oauth-client-id`, `--oauth-client-secret`, `--oauth-client-registration AUTO|CIMD|DCR`, `--oauth-resource`. `codex mcp login <name>` starts MCP OAuth (HTTP servers only). `codex mcp-server`/`codex-mcp-server` was **removed** — use `codex app-server`. TUI: `/mcp [verbose]`, `/mcp login <name>`.

### 7. Hooks / lifecycle / notify
- `features.hooks` (deprecated alias `features.codex_hooks`) enables the lifecycle-hook framework.
- Events: during a turn `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `UserPromptSubmit`, `SubagentStop`, `Stop`; on interrupt `Interrupt`; on session/subagent start `SessionStart`, `SubagentStart`; on main-thread end `SessionEnd`. (`Interrupt` and `SessionEnd` don't run for subagents.)
- Sources: `hooks.json` or inline `[hooks]` in `config.toml`, discovered next to **active config layers** — in practice `~/.codex/hooks.json`, `~/.codex/config.toml`, `<repo>/.codex/hooks.json`, `<repo>/.codex/config.toml` — plus hooks bundled with enabled plugins. All matching hooks run (multiple command hooks for one event launch concurrently); if one layer has both `hooks.json` and inline `[hooks]` Codex merges them and warns. Project-local hooks load only when the project `.codex/` layer is trusted.
- Shape: event → matcher group (`matcher` string/regex) → handlers. Handler types: `command` (fields `command`, Windows override `command_windows`/`commandWindows`, `timeout` seconds, `statusMessage`, `additionalContextLimit`, `async`) and `mcp_tool` (`server`, `tool`, `input` templates using `${field.nested}` from the event, `timeout`, `statusMessage`); `prompt`/`agent` handlers are parsed but skipped. Default `timeout` 600 s; `SessionEnd`/`Interrupt` default 1 s and cap at 3 s. Commands run with the session CWD.
- Trust model: non-managed hooks must be reviewed and trusted per exact definition (hash), via `/hooks`; changed hooks are skipped until re-trusted. `--dangerously-bypass-hook-trust` runs enabled hooks without persisted trust. Managed hooks (system/MDM/cloud/`requirements.toml`) are trusted by policy and can't be disabled in the user hook browser; `allow_managed_hooks_only = true` in `requirements.toml` ignores user/project/session hook configs (not valid in `config.toml`).
- `notify` (separate legacy mechanism): top-level `notify = ["cmd", …]` — "Command invoked for notifications; receives a JSON payload from Codex". Not allowed in project-local config. Deeper payload/event semantics: UNVERIFIED (config reference is the only documented source). TUI-side notifications are configured separately via `[tui] notifications/notification_method/notification_condition`.

### 8. Non-interactive use (`codex exec`) and sandboxing
- `codex exec` (short `codex e`): prompt as argument (or `-`/stdin; piped stdin is additional context when a prompt is also given); progress → stderr, final agent message → stdout. Subcommands: `codex exec resume [--last|--all|<SESSION_ID>] [PROMPT]`, `codex exec fork <SESSION_ID|name> [PROMPT] [--image]`, `codex exec review [--uncommitted|--base <BRANCH>|--commit <SHA> [--title]] [PROMPT]`.
- Flags (from `codex-rs/exec/src/cli.rs`): `--json` (alias `--experimental-json`; JSONL events `thread.started`, `turn.started|completed|failed`, `item.started|completed`, `error`), `-o/--output-last-message <FILE>`, `--output-schema <FILE>` (JSON Schema for the final response), `--color`, `--ephemeral`, `--skip-git-repo-check`, `--ignore-user-config`, `--ignore-rules`, `--strict-config`, `--thread-source`, `--cyber-access-program`; plus shared options (§2): `-m/--model`, `-s/--sandbox`, `-C/--cd`, `--add-dir`, `-p/--profile`, `--oss`, `--local-provider`, `--approve-for-me`, `--dangerously-bypass-approvals-and-sandbox`/`--yolo`, `--dangerously-bypass-hook-trust`, `--worktree` (new/`fork` runs; conflicts with `resume`, `review`, `--ephemeral`, `--ignore-user-config`).
- `--full-auto` is **no longer supported** — migrate to `--sandbox workspace-write` or `--approve-for-me` (routes approvals through automatic review with the workspace-write sandbox). Default `codex exec` sandbox is **read-only**. A Git repository is required unless `--skip-git-repo-check`. `--ephemeral` (and `--output-schema`, `-o`, images) require a prompt. With `CODEX_API_KEY` set inline, exec/review/SDK can run without interactive login.
- Linux sandbox: requires `bubblewrap` (`sudo apt install bubblewrap` / `sudo dnf install bubblewrap`); Codex uses the first `bwrap` on `PATH`, else a bundled helper that needs unprivileged user-namespace creation; Ubuntu 24.04 may need the `bwrap-userns-restrict` AppArmor profile (or `kernel.apparmor_restrict_unprivileged_userns=0`). Implementation crate `codex-rs/linux-sandbox` (`bwrap.rs`, `bundled_bwrap.rs`, `seccomp.rs`, `linux_run_main.rs`) with workspace deps `landlock = 0.4.4` and `seccompiler = 0.5.0` (`codex-rs/Cargo.toml`). macOS uses Seatbelt; Windows uses the native Windows sandbox (MXC legacy/`unelevated`). Probe locally with `codex sandbox linux|macos|windows [--permissions-profile <name>] [COMMAND]…` (alias `codex debug`; platform aliases `codex sandbox landlock`, `codex sandbox seatbelt`).
- Trust model: sandbox = technical boundary (what commands can touch), approval policy = when Codex must ask. Presets: Auto (`--sandbox workspace-write --ask-for-approval on-request`), read-only browsing (`read-only` + `on-request`), CI read-only (`read-only` + `never`), auto-review (`-c approvals_reviewer=auto_review`), full access (`--dangerously-bypass-approvals-and-sandbox`, alias `--yolo`). Untrusted/unknown projects start in `read-only` until trusted; `[projects."<path>"] trust_level = "untrusted"` requires approval for commands and disables project-local config. In `workspace-write`, `<writable_root>/.git` (and a resolved gitdir pointer target) is force read-only; `<writable_root>'s temp dirs and `/tmp` are writable unless excluded; network is **off** unless `sandbox_workspace_write.network_access = true`; command networking can be constrained by `features.network_proxy` (allowlist-first; `deny` wins; `*.example.com` subdomains only, `**.example.com` apex+subdomains, global `*` allow; `allow_local_binding=false` blocks loopback/private) — admin `experimental_network` is separate. Command-prefix rules: `~/.codex/rules*` + `codex execpolicy check --rules <file>`; `--ignore-rules` skips user/project rules.

### 9. Sessions / state
- Session rollouts live under `$CODEX_HOME/sessions`; archived ones under `$CODEX_HOME/archived_sessions` (`codex-rs/rollout/src/lib.rs:86-87`: `SESSIONS_SUBDIR = "sessions"`, `ARCHIVED_SESSIONS_SUBDIR = "archived_sessions"`).
- `$CODEX_HOME/history.jsonl` when history persistence is enabled (`[history] persistence = "save-all" | "none"`, `history.max_bytes` caps file size by dropping oldest entries); other per-user state (logs, caches, SQLite state DB at `sqlite_home`) also lives under `CODEX_HOME`.
- Commands: `codex resume [SESSION_ID] [--last] [--all] [--include-non-interactive] [-C/--cd DIR]` (accepts model/sandbox overrides, not `--worktree`; prompts when CWD differs from the saved CWD unless `tui.resume_cwd = "current"|"session"`, with explicit `-C` winning); `codex fork [SESSION_ID] [--last] [--all] [--worktree]` (worktree form requires an explicit session id, no `--last`/picker); `codex archive <SESSION>` / `codex unarchive <SESSION>`; `codex delete <SESSION> [--force]` (`--force` only with a UUID); `codex exec resume …` / `codex exec fork …` for non-interactive; `--ephemeral` for no persisted rollout files. In-TUI: `/resume`, `/fork`, `/archive`, `/delete`, `/new`, `/rename`, `/side` (`/btw`).
